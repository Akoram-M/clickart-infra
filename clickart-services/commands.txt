docker commands
---------------
1.open mongodb in terminal

2. open postgresql database in terminal 
docker exec -it clickart-postgres-1 psql -U test -d orders_db

open postgresql inventory database in terminal
docker exec -it clickart-postgres-1 psql -U test -d inventory_db

3.Destroy the containers and their attached volumes:
docker compose down -v

4.Purge any lingering orphaned volumes from your Mac just to be safe:
docker volume prune -f

5.Rebuild the architecture from scratch:
docker compose up -d

6.Ensure your infrastructure containers are powered on:
docker compose start

7.Power OFF docker containers:
docker compose stop

8.Reboot the network
docker compose up -d --force-recreate
docker compose up -d --force-recreate notification-service

docker logs -f clickart-product-service

docker logs -f clickart-inventory-service

Build repos 
+++++++++++
Phase 1: The Compilation Pipeline (Host Machine)

cd /Users/akorammohandoss/workspace/backend/Clickart/clickart-bom
mvn clean install

2. Compile the Microservices

cd /Users/akorammohandoss/workspace/backend/Clickart/clickart-services

cd config-server && mvn clean package -DskipTests && cd ..
cd discovery-server && mvn clean package -DskipTests && cd ..
cd product-service && mvn clean package -DskipTests && cd ..
cd inventory-service && mvn clean package -DskipTests && cd ..
cd order-service && mvn clean package -DskipTests && cd ..
cd notification-service && mvn clean package -DskipTests && cd ..
cd api-gateway && mvn clean package -DskipTests && cd ..

Phase 2: The Containerization Pipeline (Docker Daemon)

cd /Users/akorammohandoss/workspace/backend/Clickart/clickart-services

cd config-server && docker build -t clickart/config-server:1.0 . && cd ..
cd discovery-server && docker build -t clickart/discovery-server:1.0 . && cd ..
cd product-service && docker build -t clickart/product-service:1.0 . && cd ..
cd inventory-service && docker build -t clickart/inventory-service:1.0 . && cd ..
cd order-service && docker build -t clickart/order-service:1.0 . && cd ..
cd notification-service && docker build -t clickart/notification-service:1.0 . && cd ..
cd api-gateway && docker build -t clickart/api-gateway:1.0 . && cd ..

Phase 3: The Orchestration Pipeline (Docker Compose)

1. Clean the Slate

cd /Users/akorammohandoss/workspace/backend/Clickart/clickart
docker compose down -v
(The -v flag aggressively deletes the old database volumes. We want a perfectly clean state).

3. Boot the Fleet
cd /Users/akorammohandoss/workspace/backend/Clickart/clickart
docker compose up -d

Phase 4: The Verification Protocol

1. Tail the Edge Server
docker logs -f clickart-api-gateway

inject query

docker exec clickart-postgres-1 psql -U test -d orders_db -c "CREATE DATABASE keycloak_db;"

Step 5: The Boot Sequence
Tear down the old network: docker compose down -v

Boot the new network: docker compose up -d

Add a Data Source -> Select Prometheus -> URL: http://clickart-prometheus:9090 -> Save & Test.

Go to Dashboards -> Import -> Enter ID 4701 (JVM Micrometer Dashboard) -> Select your Prometheus data source -> Load.

k8s
**********
1.Run this command to expose your current configuration state and list all known clusters:
kubectl config get-contexts

2.Run this command to switch the active context:
kubectl config use-context docker-desktop

3.Verify the connection successfully hits the API server:
kubectl get nodes

4.Apply the namespace:
kubectl apply -f k8s/namespace.yaml

5.Apply the Redis deployment:
kubectl apply -f k8s/redis.yaml

6.Verify the Pod is running and physically allocating memory:
kubectl get pods -n clickart

7.Apply the PostgreSQL manifest:
kubectl apply -f k8s/postgres.yaml

8.Apply the Kafka manifest:
kubectl apply -f k8s/kafka.yaml

9.Watch the cluster actively provision the containers. 
Run this command until all three pods (Redis, Postgres, Kafka) show a status of Running:
kubectl get pods -n clickart -w

10.To clean up the stuck pods instantly, forcefully delete the deployment and let Kubernetes recreate it from scratch:
kubectl delete deployment kafka -n clickart

11.Verify the configuration actually changed:
kubectl describe pod -l app=kafka -n clickart | grep Image:

12.Execute this exact command to extract the logs from the last crashed instance:
kubectl logs deployment/discovery-server -n clickart --previous
